# Console UI/UX Review Walkthrough

A running, user-perspective walkthrough of the Console. This is a **working
document**, not a behavioral contract: [console-ui.md](console-ui.md) still owns
the interaction contracts, and this file only records what we walked through,
what we found, and what we decided.

Method: experience the Console as a user would, one area at a time. When an
issue worth fixing appears, stop, report it, agree on a fix, ship it, redeploy,
verify, then resume. Check items off as they pass.

Reference: `.agents/skills/ui-ux-pro-max/SKILL.md` for the rule catalog.

Environment:

- Read-only exploration uses the existing deployment at `http://127.0.0.1:9923`.
  From inside a container the Service rejects any non-loopback `Host`, so
  forward `127.0.0.1:9923` to `host.docker.internal:9923` (e.g. `socat`) and
  keep the loopback URL.
- Anything mutating runs a throwaway Service with `AIBOX_ROOT` under
  `/private/tmp`, seeded with its own data, and removed afterwards.

## Cross-Cutting Visual System

These are the "why does it feel off" candidates. They are checked once across
the whole app rather than per page.

- [x] **C1 · Alignment and content measure** — do related values sit near their
      labels, or are they flung to opposite edges of a wide container?
      *Fixed for Tenants, Configs, Sessions, and Requests. Overview is deferred
      to O4 because the measure exposes the Tenant table's wrapping.*
- [x] **C2 · Type hierarchy** — is the page > panel > section > row > metadata
      ladder legible, or does everything land within a few px and one weight?
      *Fixed app-wide. Overview's off-ladder weights ride along with O4.*
- [x] **C3 · Surface and boundary** — can you tell a card, a toolbar, a list row,
      and the canvas apart, or is it all near-white on near-white?
      *Fixed in the token layer. Empty detail panes still differ by module —
      Requests shows the canvas, the catalog modules stay white — which is now
      visible and rides with the per-module items.*
- [x] **C4 · Spacing rhythm** — one 4/8px scale, consistent section spacing,
      intentional whitespace instead of leftover whitespace.
      *Section rhythm unified and the scale rebuilt on a two-pixel base. The
      remaining raw values inside rows, toolbars, and controls are untouched
      and ride with their own areas.*
- [x] **C5 · Color semantics** — status, danger, links, and accents carry
      meaning; no "sea of blue" where every cell is a link.
      *Accent moved from the Overview table to the shell. Dark `--viz-model`
      still equals the dark accent; left alone because the chart bar needs the
      extra lightness and a series carrying the brand colour is not a
      conflict.*
- [x] **C6 · Iconography** — one family, one stroke weight, consistent sizes,
      no decorative icon clusters without labels.
      *All 194 icons migrated to a five-step TypeScript scale and one stroke
      weight. Whether an icon cluster needs a label is an interaction question
      and rides with C7.*
- [x] **C7 · Interaction states** — rest / hover / active / selected / focus /
      disabled are all distinguishable and consistent.
      *Press and focus rebuilt. Disabled was already tokenized and consistent,
      so it was left alone.*
- [x] **C8 · Motion** — transitions convey cause and effect; reduced-motion
      respected; no snapping state changes.
      *Timing discipline was already sound; the gap was coverage. Whether a
      given surface eases its fill turns on which element a component puts the
      class on, so that one is pinned by the sweep rather than by a test.*
- [x] **C9 · Density** — an operations console should read as dense and
      confident, not as a marketing page with a table in it.
      *Rows and padding measured fine; the marketing tell was four values
      promoted above their own siblings. The Timing waterfall was checked and
      left alone: its four two-pixel bars are the finding, not a defect.*

## Shell

- [x] **S1 · Brand block** — logo, product name, tagline: does it earn its space?
      *Kept as is. The tagline costs 18px in a sidebar with 619px of slack
      below the nav, so cutting it buys no density.*
- [x] **S2 · Module nav** — active state legibility, hover, icon/label pairing,
      keyboard traversal.
      *The current module's fill was the faintest in the vocabulary. Fixed with
      the selected step plus weight; the ladder is now checked on the shell too.*
- [x] **S3 · Sidebar utilities** — resource links, theme control, version,
      collapse affordance and its discoverability.
      *The utilities themselves were sound. Pulling the thread on the collapse
      control's missing name found that `IconButton` had lost its tooltip.*
- [x] **S4 · Collapsed sidebar** — icon-only mode, tooltips, active state.
      *Checked and clean: nav items gain a `title` when collapsed, the divider
      survives, and the new selected fill reads at 56px width.*
- [x] **S5 · Page heading and topbar** — heading placement, focus movement on
      module change, skip link.
      *Checked and clean. One Tab reaches the skip link, Enter moves focus to
      `#main-content`, and the following tab stops are the page's own controls.
      A module change moves focus to `main` and retitles the document
      (`Tenants · AIBox`); `main` suppresses its ring, which is right for a
      programmatic landing. The desktop `h1` is deliberately screen-reader
      only and becomes the visible narrow top bar heading at 900px.*
- [x] **S6 · Notification stack** — placement, stacking, dismissal, contrast.
      *Found a refused Tenant delete failing completely silently, and behind it
      no rule for which failures notify. Fixed by splitting the two error kinds:
      a lasting condition stays inline with its retry, an event that already
      happened toasts. Also noted for later: the toast stack is centred on the
      viewport rather than on the content column, so with the sidebar expanded
      it sits ~128px left of the content it refers to.*
- [x] **S7 · Operation panel** — latest Management Operation across modules,
      collapse behavior, visual weight.
      *Four defects with one cause: the shared long-task surface was built as a
      log window rather than a status surface. Fixed the occluding collapsed
      bar, the log that never followed its own stream, the terminal states that
      rendered identically, and the missing elapsed time. Left noted: the
      footer says "Terminal state" beside a monospace log, where "terminal"
      reads as a shell rather than as a final state.*

## Overview

- [x] **O1 · Service / Docker / Runtime Image strip** — scannability, healthy vs
      degraded legibility, Build action placement.
      *The strip was the one status surface speaking its own language. Fixed by
      adopting the shared treatment; Build placement was measured and left
      alone.*
- [x] **O2 · Environment details disclosure** — affordance and target size.
      *The affordance and target size were both fine. What was wrong: it forgot
      it had been opened, while hiding the two values that say which instance is
      on screen, and its rows alternated height because a pane-sized control sat
      in a text line. Fixed by persisting the state and giving `IconButton` a
      text-sized step — which also fixed a live touch-target bug in Sessions.*
- [x] **O3 · Attention list** — warning presentation, drill-in affordance.
      *The panel was a horizontal text run whose severity rode on hue alone.
      Rebuilt as a severity-ordered list with a shape per tone, one row per
      condition, and a stated total. The label column's ragged right edge was
      measured and left: the detail column aligns, and the varying gap is
      ordinary column behaviour, not the misalignment it first looked like.*
- [x] **O4 · Tenant status table** — column semantics, link density, row rhythm,
      truncation and wrapping at narrower widths.
      *Both deferred notes were wrong and are corrected in finding 17: the
      wrapping is at ≤1420px, not 1440, and `--weight-medium` has eight users
      across the app rather than being this table's alone. The two real
      defects — phrases breaking inside themselves at every laptop width, and a
      third of the table's tab stops leading where a sibling already led — are
      fixed. Column semantics and row rhythm were measured and left: the 4×4
      grid reads correctly and the row-height spread above 1420px is drift rows
      carrying one more line, which is content, not rhythm.*
- [x] **O5 · Topology view** — readability, node hierarchy, keyboard navigation,
      view switch.
      *The view was removed rather than repaired, and the reason was
      structural: there was nothing for it to draw. `agents: [AgentKind::Codex,
      AgentKind::Claude]` in the coordinator fixes every Tenant at three
      children and every Agent at three more, with no cross-links, so the
      diagram's shape could not vary — the only variable was the Tenant count,
      already stated in the heading above it. Measured at 1440: the expanded
      tree was 1993px against the List table's 578px, 2.46 screens of scroll
      against zero, 11 clicks against zero, with 18.6% of the canvas inked and
      a canvas width fixed at 760/1016px by tree depth alone, leaving 53% of a
      1920px pane permanently blank. It also lost information the List keeps:
      `testing` reads `No recorded application` in the table and nothing at all
      on its card. Its one addition — eight bare `Sessions` links with no data
      — moved into the List as counted links, which needed a real session count
      rather than the empty link. Three defects died with it: a view choice
      that persisted across modules but not across reload, every node being its
      own tab stop (54 expanded) while arrow keys also navigated, and a tree
      with no `role="tree"` whose computed `position`/`setSize` fed nothing.
      Net −928 lines. Finding 20.*
- [x] **O6 · Empty / degraded states** — no Tenants, Docker unavailable, build
      failure.
      *Five states walked: fresh root with Docker missing, Docker present with
      the image missing, a failed topology read, zero Tenants, and a failed
      build. The messages and the Build promotion were sound; the empty
      Tenant list is unreachable in practice because `default` always exists,
      and a failed build is the Operation panel's job (S7). The defect was
      that every recovery control in the attention panel had no affordance at
      rest. Finding 21.*
